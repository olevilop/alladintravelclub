# Круизные Лайнеры — каталог + фундамент под детальные страницы

## Цель
Сделать страницу `/liners` со списком всех уникальных судов из круизных туров (классика + экспедиция). Карточка появляется один раз на каждое уникальное судно (ключ — `shipName`), даже если на этом судне несколько круизов. Параллельно заложить структуру данных под будущие отдельные страницы каждого лайнера.

## Шаг 1. Модель данных лайнера

Создаём новый файл `src/data/liners.ts` со справочником судов. Это станет единым источником правды и для карточек на `/liners`, и для будущих страниц `/liner/:slug`.

```ts
export interface Liner {
  slug: string;            // URL: /liner/scenic-eclipse
  name: string;            // "Scenic Eclipse 6*"
  image: string;           // главное фото (Hero + карточка)
  shortDescription: string;// 1–2 предложения для карточки на /liners и для хлебных крошек
  longDescription?: string;// абзацы для будущей детальной страницы
  specs?: { label: string; value: string }[];  // тех. характеристики
  cabins?: { name: string; description: string; image?: string }[];
  deckPlanImage?: string;
  gallery?: string[];
}
```

На этом шаге наполняем поля `slug`, `name`, `image`, `shortDescription` для всех уникальных `shipName`, встречающихся в `tours.ts` у туров с `category === "classic" | "expedition"`. Остальные поля (`specs`, `cabins`, `deckPlanImage`, `gallery`, `longDescription`) пока оставляем пустыми — заполнишь потом, когда будем делать детальные страницы.

`shortDescription` — короткий рекламный абзац под фото в карточке, тот же текст потом ляжет в верх детальной страницы и под хлебные крошки.

## Шаг 2. Связка тура и лайнера

В `tours.ts` уже есть `shipName`. Чтобы строго матчить, добавляем туру опциональное `shipSlug?: string`. Если оно не задано — фоллбек по совпадению `shipName` (нормализуем, убираем «5*», «6*»). Это позволит:
- на `/liners` показать карточку только если есть совпадение в справочнике;
- на будущей странице `/liner/:slug` отфильтровать «Круизы на этом лайнере».

## Шаг 3. Страница `/liners`

Новый файл `src/pages/cruises/LinersPage.tsx`.

Структура:
1. `Navbar`
2. **Hero** (full-width, ~75vh) — общая обложка раздела с заголовком «Круизные Лайнеры» и подзаголовком про премиальный флот. Картинка — отдельный hero-ассет.
3. `Breadcrumbs`: Главная → Круизы → Лайнеры
4. **Сетка карточек** — `grid-cols-1 sm:grid-cols-2 lg:grid-cols-3`, gap 6. Сортировка по алфавиту имени судна.
5. `SpecialOffers`, `NewsletterSocial`, `Footer`

**Карточка лайнера** (визуально в одном ключе с TourCarousel-карточкой, но без цены/дней):
- фото 16/10
- имя судна (serif)
- `shortDescription` (3–4 строки, `line-clamp-3`)
- кнопка-ссылка «Подробнее о лайнере» → `/liner/:slug` (страницы пока нет — на этом шаге кнопка ведёт на `#`/disabled, либо открывает первый тур с этим судном; см. вопрос ниже не ставлю — выберу «открывать первый тур» как мягкий фоллбек до детальных страниц)

## Шаг 4. Навигация

В `src/components/Navbar.tsx` в dropdown «Круизы» добавляем первым пунктом «Все лайнеры» → `/liners` (и в десктоп, и в мобильное меню).

В `src/App.tsx` добавляем маршрут:
```tsx
<Route path="/cruises/liners" element={<LinersPage />} />
```
Используем путь `/cruises/liners` (а не `/liners`), чтобы хлебные крошки логично ложились под раздел «Круизы».

## Шаг 5. Что оставляем на следующий заход
- Страница `/liner/:slug` с Hero судна, тех. характеристиками, описанием, каютами, планом палуб, каруселью фото и блоком «Круизы на этом лайнере». Уже сейчас вся модель данных и связка `shipSlug` будут готовы — останется только сверстать страницу и заполнить `specs/cabins/gallery` в `liners.ts`.

## Технические детали
- Дублирования карточек избегаем через `Map<slug, Liner>` при сборке списка.
- Для соответствия memory-правилу «Carousels only on home page blocks» на `/liners` используем именно сетку, не карусель.
- Цвета и типографика — только семантические токены, fontPair проекта (Cormorant Garamond + sans).
- Никаких хардкод-цен/префиксов на карточках лайнеров (там цен и нет).
