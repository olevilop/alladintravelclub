# Детальные страницы лайнеров + переход с карточки судна

## Цель
1. Создать страницу `/liner/:slug` с полной информацией о судне (Hero, тех. характеристики, описание, каюты, план палуб, круизы на этом лайнере, карусель фото, хлебные крошки).
2. На странице тура (`TourDetail.tsx`) сделать карточку судна в правом сайдбаре кликабельной — переход на страницу лайнера.
3. На `/liners` кнопку «Подробнее» переключить с фоллбека (первый тур) на `/liner/:slug`.

## Шаг 1. Расширить модель `liners.ts`
Поля `specs`, `cabins`, `deckPlanImage`, `gallery`, `longDescription` уже есть в интерфейсе — наполняем для двух флагманов с реальными ассетами (`scenic-eclipse`, `emerald-kaia`):
- `longDescription` — 2–3 абзаца авторского описания.
- `specs` — 6–8 пар: год постройки, длина, гостей, кают, экипаж, ледовый класс, флаг, языки гидов.
- `cabins` — 3–5 категорий: имя, краткое описание, плейсхолдер-фото.
- `deckPlanImage` — плейсхолдер на схему палуб.
- `gallery` — 5–6 фото (миксуем существующие ассеты + плейсхолдеры).

Для остальных лайнеров (`aqua-blu`, `scenic-spirit`, `century-legend`, `arabian-pearl`, `galapagos-explorer`, `aegean-star`) наполняем теми же полями, но c плейсхолдер-картинками — структура страницы будет одинаковой и заполнится контентом потом.

## Шаг 2. Новая страница `src/pages/cruises/LinerDetailPage.tsx`

Маршрут: `/liner/:slug`. В `App.tsx` добавляем:
```tsx
<Route path="/liner/:slug" element={<LinerDetailPage />} />
```

Структура страницы (сверху вниз):
1. `Navbar`
2. **Hero** ~70vh: фото `liner.image` фоном, тёмный градиент, в нижнем левом углу — `liner.name` (Cormorant), под ним `shortDescription`.
3. `Breadcrumbs`: Главная → Круизы → Лайнеры → `{liner.name}`.
4. **Технические характеристики** — карточка `bg-card border` с сеткой `grid-cols-2 md:grid-cols-4`, каждая ячейка: лейбл (uppercase tracking) + значение (serif). Берём из `liner.specs`.
5. **Описание** — `longDescription` в две колонки на десктопе (`md:columns-2`), serif drop cap на первой букве.
6. **Варианты кают** — сетка `grid-cols-1 md:grid-cols-3`, карточки: фото 4/3, название (serif), короткое описание.
7. **План палуб** — full-width изображение `deckPlanImage` с заголовком и подписью.
8. **Круизы на этом лайнере** — берём `tours.filter(t => findLinerByShipName(t.shipName)?.slug === slug)`. Если ≥1 — рендерим существующий `TourCarousel` (исключение из правила «карусели только на главной» — это раздел «круизы на этом лайнере», не каталог; альтернативно — простая 3-колоночная сетка карточек как на `/liners`, чтобы не нарушать правило). **Использую сетку**, чтобы остаться в рамках memory-правила.
9. **Галерея фото** — masonry/grid 3 колонки из `liner.gallery`, клик открывает lightbox через существующий `Dialog` (или просто увеличенное превью — без новой зависимости).
10. `SpecialOffers`, `NewsletterSocial`, `Footer`.

Если `:slug` не найден в `liners` — редирект на `/cruises/liners` или показ NotFound-блока.

`useEffect` со `scrollTo(0,0)` при монтировании и при смене `slug`.

## Шаг 5. Хлебные крошки
На детальной странице лайнера: `Главная → Круизы → Лайнеры → {liner.name}`, где «Круизы» ведёт на ближайший каталог (например, `/expedition-cruises`) или просто без href, «Лайнеры» — `/cruises/liners`. Использую существующий `Breadcrumbs.tsx` без изменений.

## Технические детали
- Все цвета — семантические токены, без хардкод-классов.
- Шрифты: Cormorant Garamond для заголовков, sans для тела (memory-правило).
- Никакой Framer Motion на основном контенте детальной страницы (memory-правило для tour pages — распространяю и сюда для консистентности).
- Карусели не использую (правило «only on home»). Для блока «Круизы на этом лайнере» — сетка карточек.
- Для галереи плейсхолдер-фото беру с `placehold.co` или из существующих ассетов круизов; реальные фото пользователь добавит позже.
