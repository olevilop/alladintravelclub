# План: подключение базы данных Timeweb Cloud

## Контекст и ограничение

Lovable работает только с фронтендом (React + Vite). В песочнице Lovable **нет постоянного бэкенда** — нельзя запустить Node.js/Python сервер, который бы держал прямое соединение с PostgreSQL/MySQL на Timeweb. Прямое подключение из браузера к БД Timeweb тоже невозможно (и небезопасно — креды утекут в клиент).

Поэтому для работы с Timeweb DB нужен **промежуточный API-слой**, размещённый вне Lovable. Ниже — три рабочих варианта, нужно выбрать один.

## Вариант A — Timeweb Cloud Apps (рекомендуется)

У Timeweb есть сервис **Cloud Apps** (или VDS) — там разворачивается ваш бэкенд (Node.js/Express, FastAPI и т.п.), который:
- лежит в одной сети с базой Timeweb (быстро, безопасно),
- держит креды БД у себя в env,
- отдаёт REST/JSON API наружу,
- доступен из РФ без VPN.

Фронтенд на Lovable обращается к этому API по HTTPS.

```text
[Браузер РФ] → [Lovable Frontend (CDN)] → [Timeweb Cloud App: Node API] → [Timeweb PostgreSQL]
```

## Вариант B — VDS на Timeweb со своим API

То же самое, но руками: арендуете VDS, ставите Node/PostgreSQL, поднимаете API, выдаёте домен с HTTPS. Больше контроля, больше ручной работы (nginx, certbot, systemd).

## Вариант C — Готовый BaaS, доступный в РФ

Если не хочется писать бэкенд вообще, можно взять российский/нейтральный BaaS (например, **Directus** или **PocketBase**, развёрнутые на Timeweb Cloud Apps в один клик). Они дают админку + REST/GraphQL API из коробки поверх вашей БД.

## Что я сделаю на стороне Lovable (после вашего выбора)

1. **Конфиг API URL**
   - Добавлю `VITE_API_URL` через секрет/переменную (публичная — это просто URL, не ключ).
   - Создам `src/lib/api.ts` — единый клиент `fetch` с базовым URL, обработкой ошибок и типами.

2. **Типы и слой доступа к данным**
   - `src/types/api.ts` — типы сущностей (туры, заявки и т.д.).
   - `src/api/tours.ts`, `src/api/bookings.ts` — функции `getTours()`, `createBooking()` и т.п.

3. **Интеграция с React Query**
   - У вас уже подключён `@tanstack/react-query`. Подключу хуки `useTours()`, `useCreateBooking()` поверх API-клиента.

4. **Формы**
   - Форма заявки в `TourBookingForm.tsx` и `ContactSection.tsx` начнёт реально отправлять данные на ваш API (сейчас они только показывают toast).

5. **Авторизация (если нужна)**
   - Договоримся о схеме: JWT в httpOnly cookie (надёжнее) или Bearer-токен в localStorage. Реализую клиентскую часть.

## Что нужно от вас (вне Lovable)

Я не могу за вас развернуть бэкенд на Timeweb — это делается в личном кабинете Timeweb. Понадобится:

1. Создать БД PostgreSQL/MySQL в Timeweb Cloud.
2. Поднять бэкенд (вариант A/B/C выше) и получить публичный HTTPS-адрес, например `https://api.alladintravelclub.ru`.
3. Настроить **CORS** на бэкенде, разрешив домены:
   - `https://alladintravelclub.ru`
   - `https://alladintravelclub.lovable.app`
   - `https://id-preview--579fda52-386c-4ae5-8b8e-fe430daef7ad.lovable.app`
4. Передать мне:
   - URL API,
   - описание эндпоинтов (или я предложу схему — например `GET /tours`, `POST /bookings`),
   - какие данные хранить (заявки с форм? список туров из БД? пользователи?).
